# Классическая сборка с помощью rpmbuild

Это базовый метод сборки RPM-пакетов, совместимый со всеми дистрибутивами на основе RPM (включая Fedora, RHEL и ALT). Всё происходит в пользовательском окружении без изоляции.

## Настройка окружения

### 1.Создание структуры каталогов:

```bash
    mkdir -p ~/rpmbuild/{BUILD,BUILDROOT,RPMS,SOURCES,SPECS,SRPMS}
```

### 2.Настройка ~/.rpmmacros:

```
%_topdir      %(echo $HOME)/rpmbuild
%_sourcedir   %{_topdir}/SOURCES
%_specdir     %{_topdir}/SPECS
%_builddir    %{_topdir}/BUILD
%_buildrootdir %{_topdir}/BUILDROOT
%_rpmdir      %{_topdir}/RPMS
%_srcrpmdir   %{_topdir}/SRPMS
%_build_name_fmt %%{NAME}-%%{VERSION}-%%{RELEASE}.%%{ARCH}.rpm
```

### 3.Установка зависимостей:

```bash
apt-get install rpm-build rpmdevtools
```

## Пример сборки
```
# Поместить .spec в SPECS, исходники — в SOURCES
cp myapp.spec ~/rpmbuild/SPECS/
cp myapp-1.0.tar.gz ~/rpmbuild/SOURCES/

# Собрать SRPM
rpmbuild -bs ~/rpmbuild/SPECS/myapp.spec

# Собрать бинарный RPM
rpmbuild -bb ~/rpmbuild/SPECS/myapp.spec
```

**Преимущества**
* Простота и прозрачность.
* Подходит для быстрой локальной сборки.
* Минимальные зависимости.

**Недостатки**
* **Нет изоляции:** сборка происходит в пользовательской системе → риск загрязнения зависимостями.
* **Невоспроизводима:** результат зависит от текущего состояния системы.
* **Небезопасна:** потенциально опасный код может повредить систему.

**Сценарии использования**
* Быстрая локальная сборка для тестирования.
* Обучение основам RPM.
* Сборка пакетов, не предназначенных для публикации.
